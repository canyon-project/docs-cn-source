# @canyonjs/git-diff

@canyonjs/git-diff 是一个用于在 CI/CD 流水线中检测代码变更并生成 Git Diff 内容的工具，同时支持变更代码覆盖率报告。

## 功能特性

- **流水线类型检测**：自动检测当前运行环境是 MR（Merge Request）还是普通 Commit
- **Git Diff 生成**：根据检测到的流水线类型，生成相应的 Git Diff 内容
- **变更代码覆盖率**：支持针对变更代码的覆盖率分析和报告
- **与 Canyon 生态集成**：与其他 Canyon 工具无缝协作

## 安装

您可以通过 npm 或 yarn 安装 @canyonjs/git-diff：

```bash
npm install --save-dev @canyonjs/git-diff
# 或
yarn add --dev @canyonjs/git-diff
```

## 基础使用

### 在 CI/CD 流水线中使用

```bash
# 检测流水线类型并生成 Git Diff
git-diff

# 与覆盖率报告结合使用
nyc --reporter=@canyonjs/git-diff ava
```

### 命令行选项

```bash
# 指定基准分支
git-diff --base=main

# 指定比较分支
git-diff --head=feature-branch

# 指定输出格式
git-diff --format=json

# 与覆盖率报告结合时指定输出目录
nyc --reporter=@canyonjs/git-diff --report-dir=./coverage-diff ava
```

## 流水线类型检测

@canyonjs/git-diff 能够自动检测多种 CI/CD 平台的流水线类型：

- **GitHub Actions**：检测 PR（Pull Request）或 Push 事件
- **GitLab CI**：检测 MR（Merge Request）或 Commit 事件
- **Jenkins**：检测构建类型
- **其他平台**：通过环境变量进行检测

### 检测逻辑

1. 首先检查 CI/CD 平台特定的环境变量
2. 根据环境变量判断是 MR 还是普通 Commit
3. 针对 MR，比较源分支与目标分支
4. 针对普通 Commit，比较当前提交与上一个提交

## Git Diff 生成

根据检测到的流水线类型，@canyonjs/git-diff 会生成相应的 Git Diff 内容：

### MR 场景

```bash
# 内部执行类似命令
git diff origin/main..origin/feature-branch
```

### Commit 场景

```bash
# 内部执行类似命令
git diff HEAD~1..HEAD
```

## 变更代码覆盖率

@canyonjs/git-diff 作为报告器时，能够：

1. 生成 Git Diff 内容
2. 分析变更代码的覆盖率情况
3. 生成针对变更代码的覆盖率报告
4. 高亮显示未覆盖的变更代码

### 与其他报告器结合使用

```bash
# 同时生成完整覆盖率报告和变更代码覆盖率报告
nyc --reporter=lcov --reporter=@canyonjs/git-diff ava
```

## 配置选项

### 在 package.json 中配置

```json
{
  "git-diff": {
    "base": "main",
    "format": "json",
    "reportDir": "./coverage-diff"
  }
}
```

### 环境变量配置

| 环境变量 | 描述 | 默认值 |
|---------|------|-------|
| `GIT_DIFF_BASE` | 基准分支 | `main` |
| `GIT_DIFF_HEAD` | 比较分支 | 当前分支 |
| `GIT_DIFF_FORMAT` | 输出格式 | `text` |
| `GIT_DIFF_REPORT_DIR` | 报告输出目录 | `./coverage-diff` |

## 最佳实践

1. **在 CI/CD 流水线中使用**：将 @canyonjs/git-diff 集成到您的 CI/CD 流程中，自动检测代码变更并生成覆盖率报告

2. **设置覆盖率阈值**：针对变更代码设置覆盖率阈值，确保新代码或修改的代码都有足够的测试覆盖

3. **与代码审查结合**：将变更代码覆盖率报告作为代码审查的一部分，帮助审查者了解测试覆盖情况

4. **持续监控**：通过比较不同提交或 MR 的变更代码覆盖率，持续监控代码质量

## 示例

### GitHub Actions 工作流示例

```yaml
name: Test Coverage

on: [pull_request, push]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v3
        with:
          node-version: 18
      - run: npm install
      - run: npm test -- --reporter=@canyonjs/git-diff
      - name: Upload coverage report
        uses: actions/upload-artifact@v3
        with:
          name: coverage-diff
          path: ./coverage-diff
```

### GitLab CI 配置示例

```yaml
test:
  stage: test
  script:
    - npm install
    - npm test -- --reporter=@canyonjs/git-diff
  artifacts:
    paths:
      - ./coverage-diff
```

## 常见问题

### 无法检测流水线类型

**解决方案**：手动指定基准分支和比较分支

```bash
git-diff --base=main --head=feature-branch
```

### Git Diff 内容为空

**解决方案**：确保仓库已经正确克隆，并且有足够的历史记录

```bash
# 克隆时获取完整历史
git clone --depth=0 <repository-url>

# 或在现有仓库中获取更多历史
git fetch --depth=20
```

### 变更代码覆盖率报告不显示

**解决方案**：确保测试能够生成覆盖率数据，并且 @canyonjs/git-diff 作为报告器正确配置

```bash
# 确保生成覆盖率数据
nyc --reporter=@canyonjs/git-diff --reporter=text-summary ava
```
