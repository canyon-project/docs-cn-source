# 覆盖率数据模型

> **状态**: 草稿  
> **版本**: 1.0.0-alpha  
> **最后更新**: 2025-01-XX

## 概述

本文档定义了 Canyon 覆盖率收集系统的核心数据模型。它描述了基本实体、它们之间的关系以及控制覆盖率数据如何结构化、存储和合并的不变量。

## 范围

本规范涵盖：

- 核心实体：覆盖率映射（Coverage Map）、覆盖率命中（Coverage Hit）、场景（Scene）、构建（Build）
- 身份模型：覆盖率数据如何被唯一标识
- 数据不可变性原则
- 合并语义和规则

## 非目标

本规范不涵盖：

- 实现细节（NestJS、ClickHouse、PostgreSQL）
- UI/UX 设计
- CI/CD 集成细节
- 插件实现细节

## 核心实体

### 覆盖率映射（Coverage Map）

覆盖率映射表示**插桩代码的结构**。它描述了：

- 存在哪些语句、函数和分支
- 它们在源代码中的位置
- Source Map 映射

**关键特性：**

- 创建后不可变
- 可在多个构建中重用
- 由 `mapHash` 标识

### 覆盖率命中（Coverage Hit）

覆盖率命中表示**运行时执行**数据。它包含：

- 语句、函数、分支的执行计数
- 收集时间戳
- 关联的 `mapHash` 引用

**关键特性：**

- 可变（计数可以递增）
- 轻量级（无结构信息）
- 由 `mapHash + sceneKey + timestamp` 标识

### 场景（Scene）

场景表示覆盖率收集的**执行上下文**。它描述了：

- 覆盖率如何收集（自动化、手动、回放）
- 覆盖率在何处收集（环境、触发器）
- 使用了什么工具（playwright、jest 等）

**关键特性：**

- 由结构化字段定义（source、type、env、trigger）
- 用于聚合和过滤
- 不是身份的一部分（不影响合并决策）

### 构建（Build）

构建表示**构建/执行实例**。它标识：

- 仓库（provider + repoID）
- Commit SHA
- 构建目标
- 可选：Pipeline ID、Job ID

**关键特性：**

- 每个构建实例唯一
- 用于构建级聚合
- 由 `buildHash` 标识

## 身份模型

Canyon 使用多层身份系统：

| 身份 | 用途 | 使用位置 |
|------|------|----------|
| `mapHash` | 代码结构指纹 | Hit、Map |
| `buildHash` | 构建实例身份 | Build、Hit、Map |
| `sceneKey` | 执行上下文签名 | Hit、Scene |
| `fileContentHash` | 源文件内容指纹 | Map |

### 身份规则

1. **一个身份，一个用途**：每个哈希正好回答一个问题
2. **不可变**：身份一旦分配就永远不会改变
3. **版本化**：哈希算法可以演进，但必须进行版本化

## 数据不可变性

### 映射不可变性

- 覆盖率映射创建后**不可变**
- 相同的 `mapHash` 始终指向相同的结构
- 映射可以在多个构建/版本中重用

### 命中可变性

- 覆盖率命中是**可变的**（计数可以递增）
- 具有相同 `mapHash + sceneKey` 的多个命中可以合并
- 合并保持幂等性

## 关系

```
构建 (buildHash)
  └─ 映射 (mapHash)
      └─ 命中 (mapHash + sceneKey)
```
