# 故障开放语义

> **状态**: 草稿  
> **版本**: 1.0.0-alpha

## 概述

本文档定义了 Canyon 的故障开放行为。它确立了覆盖率收集绝不能干扰应用程序执行，即使覆盖率系统本身发生故障。

## 核心原则

> **覆盖率是可观测性，不是业务逻辑。**
> 
> 覆盖率系统故障绝不能影响应用程序执行。

## 故障开放 vs 故障关闭

| 策略 | 出错时 | 影响 |
|------|--------|------|
| **故障关闭** | 抛出 / 拒绝 | 阻塞执行 |
| **故障开放** | 忽略 / 丢弃 | 执行继续 |

Canyon 对所有运行时覆盖率收集使用**故障开放**策略。

## 故障开放的应用场景

### 1. 运行时 SDK（客户端）

**规则**: 覆盖率 SDK 绝不能抛出异常。

```javascript
// ✅ 正确: 故障开放
try {
  reportHit(mapHash, hits);
} catch (error) {
  // 静默忽略
  console.debug('覆盖率报告失败', error);
}

// ❌ 错误: 故障关闭
await reportHit(mapHash, hits); // 可能抛出异常
```

**要求**:
- 所有异常都被捕获并吞掉
- 网络超时: 最大 100-300ms
- 无 await/阻塞调用
- 实施载荷大小限制（超出则丢弃）

### 2. 命中端点（服务器端）

**规则**: 命中端点始终返回 200，即使出错。

```typescript
// ✅ 正确: 故障开放
app.post('/api/coverage/hit', (req, res) => {
  try {
    processHit(req.body);
  } catch (error) {
    // 记录但不失败
    logger.error('命中处理失败', error);
  }
  res.status(200).json({ success: true });
});
```

**错误场景**:
- 无效载荷 → 丢弃，返回 200
- 缺少 mapHash → 丢弃，返回 200
- 数据库错误 → 排队重试，返回 200
- 超出速率限制 → 丢弃，返回 200

### 3. 映射-命中顺序

**场景**: 命中在对应的映射之前到达

**行为**: 
- 命中被存储（或丢弃）
- 映射查找延迟
- 关联异步发生
- 永远不要阻塞命中存储等待映射

```typescript
// ✅ 正确: 异步关联
async function processHit(hit) {
  if (!mapExists(hit.mapHash)) {
    // 存储命中以便稍后关联
    await storeHitForLaterAssociation(hit);
  } else {
    await processHitWithMap(hit);
  }
}
```

## 故障开放检查清单

### 运行时 SDK

- [ ] 所有网络调用都包装在 try/catch 中
- [ ] 配置超时（100-300ms）
- [ ] 关键路径中无 await/阻塞
- [ ] 载荷大小验证（过大则丢弃）
- [ ] 无 console.error（使用 debug 级别）

### 命中端点

- [ ] 始终返回 200
- [ ] 无效载荷被丢弃（不拒绝）
- [ ] 错误被记录但不返回
- [ ] 速率限制丢弃超额（不拒绝）
- [ ] 数据库错误不传播

### 映射端点

- [ ] 幂等性（可重试）
- [ ] 部分失败不会导致整个请求失败
- [ ] 无效映射被拒绝并返回详情（但不会导致构建失败）

## 不适用故障开放的情况

### 映射端点（构建时）

映射报告发生在 CI/CD 期间：

- **可以失败**: 构建应该知道映射报告是否失败
- **可以重试**: 幂等性，重试安全
- **可以阻塞**: 不在关键用户路径中

**例外**: 映射端点可以是故障关闭的（它是构建时，不是运行时）。

## 监控

由于错误被吞掉，监控至关重要：

### 要跟踪的指标

- 命中丢弃率（无效载荷）
- 映射未命中率（无映射的命中）
- 网络失败率
- 载荷大小分布

### 告警

- 命中丢弃率 > 1%
- 映射未命中率 > 5%
- 网络失败率 > 10%

## 最佳实践

### 1. 日志记录

```javascript
// ✅ 良好: Debug 级别
logger.debug('覆盖率命中被丢弃', { reason, mapHash });

// ❌ 错误: Error 级别（可能触发告警）
logger.error('覆盖率命中被丢弃', { reason, mapHash });
```

### 2. 重试逻辑

```javascript
// ✅ 良好: 尽力而为，不重试
reportHit(data); // 发送并忘记

// ❌ 错误: 重试逻辑（可能累积）
await retry(reportHit, data, { maxRetries: 3 });
```

### 3. 载荷验证

```javascript
// ✅ 良好: 验证并丢弃
if (!isValidHit(payload)) {
  logger.debug('无效命中被丢弃', payload);
  return; // 不要抛出
}

// ❌ 错误: 验证时抛出
if (!isValidHit(payload)) {
  throw new Error('无效命中'); // 可能导致应用崩溃
}
```

## 总结

故障开放不是「忽略错误」——它是「将应用程序执行置于覆盖率数据收集之上」。

覆盖率数据很有价值，但不是关键。应用程序执行才是关键。
